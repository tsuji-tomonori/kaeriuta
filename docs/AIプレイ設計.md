# AIプレイ設計

`tools/AIプレイ/` はゲーム本体を変更せず、`file://` で開いた実ブラウザの DOM を観測して操作するプレイ基盤である。`tools/到達可能性検査.mjs` のようなシナリオデータ直読・フラグ注入による検査とは別物として扱う。

進行処理は `tools/ブラウザ検証/進行基盤.js` に一元化する。ここには要素探索、クリック送り、特殊パートの安全な操作手順、停止検出、最終画面の採取を置く。AIプレイはペルソナによる「どの選択肢・特殊パートの候補を選ぶか」だけを渡し、同じ進行基盤を利用する。進行ロジックを別実装しない。

起動直後、AIプレイは `#ai-play-started` と `#ai-play-launch-status[data-started="true"]` を DOM に置く。前者がない場合はモジュール自体が読み込まれていない。基盤は `window.onerror`、`unhandledrejection`、`console.error` を結果へ回収し、40回変化がなければ `stalled` として本文冒頭・ボタン一覧・特殊パート名を含む最終画面を出力する。

ブラウザ側の全JSは `tools/構文検査.sh` で `.mjs` として構文検査する。Node側の `回収.mjs` は標準入力ストリームを読むため、変更時はダミーHTMLを標準入力から一度実行して確認する。

## 観測

自動プレイヤーは画面が変化するたび、次の形の観測をペルソナへ渡す。

```js
{ step, chapter, sceneId, kind: 'say' | 'mono' | 'stage' | 'choice' | 'part' | 'end', speaker, text,
  choices: [{ index, label, enabled }], part: { name, title, nodeClaim, text, options } | null,
  params: { suspicion, conviction, past, plan, alive }, flags: { past: null, plan: null, alive: null }, items: null }
```

本文はメッセージ窓、章名は `#chapter-title`、場面IDは `#app.dataset.sceneId`、選択肢と特殊パートは可視ボタンから読む。HUD の「疑惑」「確信」と3系統フラグの**個数**は各節目で採取する。反論パートでは本文の「確信度」「知りすぎ」も採取するため、`bannin` は画面に出た疑惑・確信度・知りすぎを次の一手の採点に使える。END 到達時はオートセーブ済みの `localStorage` から最終パラメータ、フラグID、アイテム、END ID を回収する。

取得できない情報もある。ゲームの実行中 `state` は `src/main.js` のモジュール内ローカル変数で `window` に公開されていないため、途中経過のフラグID・アイテムID、HUD にないパラメータ（良心・察知・知りすぎ等）は DOM/window だけでは取得できない。これらは `null` とし、最終状態だけオートセーブから補う。本体へ観測用APIを足すことはこの波の対象外である。

## 決定

各ペルソナは以下のインターフェースを満たす ES module である。

```js
export const persona = { id: 'suiri', name: '完全主義の推理者', description: '…',
  decide(observation, memory) { return { choice: 2, reason: '書斎の伏線を潰したい' }; } };
```

通常選択は `choice`、特殊パートは `part`（いずれも表示順 index）、読み送りは `advance: true` を返す。全決定は日本語の `reason` とともにログへ残る。`memory` はブラウザ内のペルソナ専用オブジェクトであり、周回間では共有しない。

### 評価関数

通常選択・特殊パートとも、候補を先に見つける方式ではなく、**表示中の全候補**に `score(option, observation, memory)` を適用して最大値を選ぶ。共通採点器は、選択肢だけでなく直前本文・章名・HUD/特殊パートのパラメータ・直前に選んだ文言を材料にする。語は完全一致ではなく、探索、隠蔽、準備、配慮、対話、安全、非合理といった複数語群への部分一致を加点・減点する。改稿で表現が変わっても、行動の種類を拾える設計である。

各候補は必ず非ゼロの得点を持ち、ラベル由来の安定した微小差と表示順の微小差で非同点にする。ただしこれは「根拠がある」ことを偽装しない。各ペルソナは語群に掛からない台詞にも、具体性（対象語・固有名詞の量）と表示順についての補助基準を持つ。推理・感情・逆転・見切り発車は具体的な対象を言う提案を、保身・逃走・即興・操りは簡潔な提案を重く見る。表示順も、即興・操り・保身は先頭、逆転・感情・見切り発車・裏取りは後段を選ぶ明示的な基準である。方針語・本文・この補助基準のいずれにも十分な差が出ない場合は `diagnostic.grounded=false` とし、既定動作として記録する。理由には候補ごとの採点値と、加減点になった手掛かりを残す。

目標ENDを持つペルソナには、通常の全候補採点と並行して「目標に必要な分岐」を意味語で照合する `requiredRoutes` を置く。該当候補には通常の重みを大きく上回る加点を行うため、これは固定indexや表示順のハードコードではなく、目的関数の制約である。改稿で言い回しが変わっても、行動の意味語で追従する。

### 特殊パートの判断

特殊パートにも通常選択とは別の方針を必ず設定する。反論は「反証・沈黙・転嫁」、自由行動は画面に示される手掛かり・退路・対話、手毬唄ボードはカード配置の順序、共同推理は `P1`〜`P4` のフェーズと「自分が暴く／コウナンに任せる／律の遺したもの」を採点対象にする。固有の主張文やカードIDではなく、UIが出す役割とフェーズを使うため、シナリオ改稿に依存しない。

共同推理はノード選択の次に提示方法を選ぶ二段UIである。AIプレイは画面更新を観測し、提示方法も同じペルソナ採点器で選んで `part:jointReasoning:method` として記録する。`suiri` はP1から順に自分で崩し、`bannin` はコウナンへの代理、`kanjou` は律の遺したもの、`sokkyou` は常に最初、`ura` は後半フェーズ・沈黙・転嫁を優先する。これらは反論・自由行動・手毬唄にも対応する専用基準を持つ。

`bannin` は疑惑が35以上なら隠蔽・安全を強く加点して探索・直接発言を減点し、確信度が60以上なら準備・沈黙を追加で加点する。反論中に知りすぎが観測された場合は直接発言をさらに避ける。これにより、単に先頭を選ぶ `sokkyou` と目的関数が分かれる。`sokkyou` は短さ・会話・その場で済む行動を加点し、探索・準備を減点する。ほかの3者も、推理は探索/証拠、感情は配慮/対話、裏取りは安全策を外す非合理性を重視する。

## ペルソナ

- `suiri`: 🕯📜👁を取りに探索・反証・共同推理・告白を優先する謎解き層。
- `bannin`: 沈黙・転嫁・犯行準備・実行・脱出を優先し、知りすぎを避ける倒叙層。
- `kanjou`: 栞の良心、蘭子、母、告白を優先する物語・情緒層。
- `sokkyou`: 短く手間の少ない会話を選ぶ。表示順は弱い読みやすさの補助材料にすぎず、探索・準備には減点を掛ける可読性検証層。
- `ura`: 転嫁や物証不提示など非合理な選択を好む、失敗分岐・ビターENDの境界検証層。
- `toubou`: A-2脱出。書斎→家政婦→共犯者の部屋→犯行準備、死体の手元→安置室→主治医→厨房→**五番の唄と地図の照合**、凶器、館を出る→旧道を下る、を必須分岐として高く採点する。旧道照合を逃走条件として明示し、推理ショーでは代理へ渡す生存本能層。
- `ayatsuri`: 自分で調べず、提示順と計画に従ってA-3操り人形を狙う受動性層。
- `gyakuten`: A-4逆転。書斎→家政婦→共犯者の部屋→犯行準備、死体の手元→安置室→主治医→厨房→書斎、**凶器を取る**、階段の下→挙手で割込→皆の前で読み上げる、を必須分岐として高く採点する。実行ルートと自力の共同推理で逆転を狙う賭けの層。
- `mikiri`: B-3口封じ。自由行動では探索・証拠集めを避け、**このまま扉を叩く**→**部屋に籠る**→**五番の夜に扉を開ける**だけを必須分岐として高く採点する。物証を待たず率直に告白・行動して察知を上げる焦りの層。

手毬唄ボードだけは「カード選択→空欄へ配置」の二段操作であるため、ペルソナ判断の間に基盤がこの安全なUI手順を補助する。何を置いたかと理由は決定ログに残る。

## 回収とログ

ブラウザは結果 JSON を 24KB ごとの base64 チャンクとして `#ai-play-result` に置く。`--dump-dom` の一要素が長文で切れることを避け、`回収.mjs` が全チャンクを連結して Markdown と JSON に復元する。1ペルソナにつきChrome実行は1回で完結する。

`ログ/<ID>.md` は順番どおりの本文、選択肢全文、選択と理由、特殊パート画面、HUD節目、最終結果を読むための一次資料である。末尾には「判断品質の自己診断」として、総選択回数、方針に結び付く根拠で選べた回数、根拠が薄く補助基準へ落ちた回数と割合、そのときの候補文言一覧を出す。この割合が20%以上なら、その一覧を手掛かりに語群・状況加点を追加する。

振り返りは定型感想を出さない。画面連続観測から、疑惑・確信度・察知・良心の変動幅上位2件と直前本文、最大・最小の得点差選択、自由行動で表示されたが選ばなかった情報、反論の確信度推移、共同推理で崩したノード数・未完了数・提示方法を出す。END条件そのものは本体からDOMへ公開されないため、未達条件を推測で断定せず、その制約と最終パラメータ・フラグ・選択ログを併記する。`ログ/サマリ.json` はこれらの診断・分析・振り返りを機械可読で集約する。
