# 実装メモ

- パラメータは初期段階の調整可能な提案値として、0〜100系と関係性の-10〜10系に分離した。詳細はデータ仕様を正とする。
- 条件は文字列式を禁止し、JSONデータを再帰評価する。シナリオ担当がJavaScriptを混ぜずに済み、`node:test` で検証できるため。
- manifestの画像は存在確認後に使い、欠けている間はCanvasプレースホルダへ必ず切り替える。アセット生成波が空ディレクトリのまま進めてもゲームが落ちない。
- `choice.goto` は専用の `{t:'label', id}` を参照する。`stage` は常に演出表示であり、アンカーとの兼用を禁止した。実行位置は `executionStack` に保存し、`if` を分岐配列のフレームとして処理するため、シナリオ定義を変更しない。分岐内セーブもこのスタックをそのまま往復する。
- プロローグ末尾は `chapter1` への `jump` として統合済みである。シーン参照・ラベル・特殊パートIDの不整合は `node tools/シナリオ検証.mjs` で検出する。
- 特殊パートは実装・`call`結線済みで、終了時に返すeffectsを共通の状態更新へ適用する。入力・出力の状態契約はデータ仕様を正とする。
