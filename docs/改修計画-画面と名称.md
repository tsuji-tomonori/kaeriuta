## 課題1【最優先】立ち絵が重なって表示される

### 症状
画面に前の場面の人物が残ったまま、次の人物が上に重ねて描画される。依頼者のスクリーンショットでは、佐伯の背後に剛蔵が、真壁の背後に藤乃が、家政婦の背後に剛蔵が、宗玄の背後に宇野が、それぞれ半分見えている状態になっている。

### 原因(特定済み)
`src/ui/character-layer.js` の `show()`:

```js
show(id, expr, pos, action) {
  const key = `${id}-${pos}`; let img = container.querySelector(`[data-key="${key}"]`);
  if (action === 'fadeOut') { img?.remove(); return; }
  if (!img) { img = document.createElement('img'); ... container.append(img); }
  ...
}
```

- 要素の識別キーが **`人物ID + 位置`** になっているため、**同じ位置に別の人物が来ると別のキーになり、新しい `img` が追加される**。前の人物の `img` は消えない
- `docs/データ仕様.md` では `action` に `fadeIn | replace | fadeOut` を定義しているが、**`replace` を処理する分岐が存在しない**。`fadeOut` でしか要素を消せない
- シナリオ側は `action:'replace'` を多用しているが、実装が無視している

### 修正方針
- **識別キーを「位置」だけにする。**1つの位置には常に1人しか存在しないようにし、同じ位置に別人物が来たら差し替える
- `action` の3種を仕様どおり実装する
  - `fadeIn`:その位置に新規表示(フェードイン)
  - `replace`:その位置の人物を差し替える
  - `fadeOut`:その位置から退場させる
- **場面転換(`{t:'bg'}` による背景変更)のときに、立ち絵レイヤーを全消去する**か検討すること。シナリオ側が明示的に退場させ忘れている場面が多数あるため、背景が変わったら人物も一旦リセットするのが安全。ただし同一場面内での背景変更(時間経過など)で人物が消えると不自然になる場合があるので、**シナリオデータを確認したうえで判断**し、判断理由を `docs/実装メモ.md` に記録すること

### 自己検証(必須)
表示ロジックを**純粋関数として切り出し**、`node --test` でテストを書くこと。最低限:

- 同じ位置に別の人物を `replace` で表示すると、**その位置の人物が1人だけ**になる
- `fadeOut` でその位置が空になる
- 3つの位置(left/center/right)にそれぞれ別人物を置いたとき、**同時に存在するのは3人まで**
- 同じ人物を同じ位置に連続で表示しても要素が増えない

## 課題2【最優先】立ち絵の下端が切れて宙に浮いて見える

### 症状
人物の腰のあたりで水平にぶつ切りになり、その下に背景が見えている。切り抜きの失敗のように見える。

### 原因(特定済み)
立ち絵は**全身からバストアップへトリミング済み**(33点すべて、`tools/構図統一.py` による)。一方 `src/styles/main.css` の配置は全身立ち絵を前提にしたままである:

```css
.character { position:absolute; height:82%; bottom:8%; width:31%; object-fit:contain; }
```

`bottom:8%` で**画面下端から浮かせている**ため、トリミングした下端(腰の切断面)がそのまま見えてしまう。

### 修正方針
- **立ち絵の下端を画面の下端に接地させる**(`bottom:0`)。加えて `height` を上げ、**腰の切断面が画面外へフレームアウトする**ようにする。こうすると「切れている」ではなく「画面下に続いている」と読める
- メッセージウィンドウ(画面下部)と重なる領域が増えるので、**顔が隠れないこと**を優先して数値を決めること
- `width:31%` と `object-fit:contain` の組み合わせだと、縦を伸ばしても横幅の制約で拡大されない可能性がある。**縦横の指定を見直すこと**
- 3人並んだときに顔が重ならないよう、left/center/right の位置も併せて調整してよい
- 依頼者の画面は横長(1997x1085相当)である。**極端な横長でも縦長でも破綻しない**指定にすること

### 自己検証
Chromeが使えないため、**数値の意図と、どの範囲のアスペクト比で成立するかを `docs/実装メモ.md` に記述**すること。目視確認は依頼者が行う。

## 課題3 演出テキストが画面上部にあり、操作できると分からない

### 症状
【】で囲まれた演出文が画面上部に細い帯で表示される。クリックで送れるが、**そこをクリックすればよいと分からない**。依頼者から「上の選択肢やダイアログを選択する箇所が分かりづらい」との指摘。

### 原因
`src/styles/main.css`:

```css
#stage-note { position:absolute; z-index:6; top:13%; left:10%; right:10%; padding:.7em; ... }
```

`{t:'stage'}` ノードは `#stage-note` に表示され、**画面上部(top:13%)に配置**されている。通常の台詞・モノローグは `#message-layer`(画面下部)に出るため、**同じ「読んで送る」操作なのに、出現位置と見た目が場面ごとに変わる**。さらに送り操作を示す表示がない。

### 修正方針
- **演出テキストも通常のテキストと同じ場所(画面下部のメッセージウィンドウ)に表示する**ことを第一候補とする。読む場所が1箇所に固定され、操作が分かりやすくなる
  - 演出であることは**枠線の色や地の文とは違うスタイル**で区別する(現状 `.monologue` が枠線色を変えているのと同じ手法)
  - 【】で囲む表示は維持してよい
- 上部に残す設計を選ぶ場合は、**なぜそれが良いかを実装メモに書き**、かつ操作可能であることが明確に分かる見た目にすること

## 課題4 右下に「次へ」ボタンを置く

### 依頼者の要望
「選択肢以外は、右下に『次へ』みたいなボタンがある方が分かりやすそう」

### 現状
`src/styles/main.css` に `.advance{float:right;color:#f0ce83;line-height:1}` があるのみで、**ボタンとして認識できる見た目ではない**。

### 修正方針
- **メッセージウィンドウの右下に、明確なボタンとして「次へ」を表示する**
  - 見た目は既存の `button` スタイル(`#hud` のセーブ/タイトルへ)と揃えること
  - クリックで次へ進む。**既存のウィンドウ全体クリックでの送りも残す**(慣れた人が速く読める)
- **表示する条件**:通常の台詞・モノローグ・演出など「読んで送る」場面
- **表示しない条件**:選択肢が出ている場面、特殊パート(反論・共同推理・自由行動・手毬唄ボード)の操作待ち、END画面。これらは**プレイヤーが選ぶべき場面**なので「次へ」が出ると誤誘導になる
- 特殊パート側にも同種の分かりにくさがある場合は、**同じ考え方(進行のための操作は右下)で揃える**こと

### 自己検証
「次へ」を出す/出さない条件の判定を純粋関数として切り出し、`node --test` で検証すること。

## 課題6 探偵側3名の口調をより「らしく」する

### 依頼者の要望
「コナン君もう少しコナンクンっぽくして。蘭や小五郎も同じ」

名前は変えるが、**キャラクターの魅力は原型に近づける**。`plan/登場人物表.md` の役割定義(推理の砲台/良心の鏡/議事録たる子供)を保ったまま、話し方を強化する。

### コウナン(少年・観察者)

本作の設計上、この少年は**二つの声を持つ**。この使い分けが恐怖の核である(`plan/第三章シナリオ.md` に既に実装例がある)。

- **子供を演じているとき**:一人称「**ボク**」。語尾は「〜だよ」「〜なの?」「〜でしょ?」「〜だもん」。明るく、無邪気に、とぼける。核心を突く質問ほど無邪気に投げる(「ねえお姉さん、おとといの夜って、何時ごろお部屋に戻ったのー?」の調子)
- **素が出るとき**:一人称「**オレ**」。断定的で速い。敬語を使わない。子供の仕草が消える
- **切り替わりの瞬間を明示する。**地の文で「子供の口調ではない」「取り繕うように」と書き添え、栞(と読者)がぞっとする作りにする
- 現状の台詞は**この二層構造が薄く、最初から大人びている箇所が多い**。子供を演じる比率を上げ、素が出る場面を絞ることで落差を作ること

### 蘭子(同行者)

- まっすぐで気遣いが厚い。**相手の体調や気持ちを先に見る**
- 敬語まじりの丁寧語。「〜ですか?」「大丈夫ですか?」「こういう時こそ、です」
- 感情が素直に出る。言いにくいことも、遠回しにせず誠実に言う
- 栞の**良心を映す鏡**として機能させる。彼女に優しくされるほど栞が痛む、という関係を台詞で作ること

### 悟郎(推理ショー役の探偵)

- 声が大きい。自信過剰。**決めつけてから考える**
- 「〜なんだよ!」「〜に決まってる」「まあ待て」。酒好きで、締まらない場面がある
- ただし**推理ショーの場面だけは別人のように冴える**。この落差がキャラクターの魅力
- 現状の台詞は概して硬い。**普段の締まらなさ**を足すこと

### 作業範囲
`src/data/scenario/` 配下の全シナリオと `src/data/parts/` の台詞。**該当する台詞を洗い出し、上記の方針で書き直す。**

**文章の質を落とさないこと。**栞の一人称(48歳・図書館司書、比喩は本・紙・活字に寄せる)と、作品全体の静かな筆致は維持する。探偵側3名の台詞だけが変わる。
