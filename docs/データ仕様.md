# データ仕様

この文書が後続波のデータ契約です。JavaScriptのデータファイルはES Moduleとして `export const` で公開し、IDは英小文字・数字・`_` を用います。表示文・コメントは日本語です。

## シナリオ

1シーンは `{ id, title, chapter, nodes: [...] }`。ノードは上から逐次実行されます。会話・モノローグ・演出指定はクリック送り、状態変更や画面変更は自動で次へ進みます。

新しいsceneは `src/data/scenario/index.js` の `scenes` レジストリにも必ず追加します。実行時と `tools/シナリオ検証.mjs` はこの同じレジストリを読むため、未登録sceneへの`jump`を検出できます。

```js
{ t:'bg', id:'bg_hall_night', transition:'fade' }
{ t:'chara', id:'chara_shiori', expr:'uneasy', pos:'left', action:'fadeIn' }
{ t:'cg', id:'cg_manuscript' }
{ t:'say', who:'shiori', text:'台詞', voice:'任意の音声ID' }
{ t:'say', who:null, text:'地の文' }
{ t:'mono', text:'栞のモノローグ' }
{ t:'stage', text:'【演出指定】' }
{ t:'label', id:'study_done' } // 分岐先の無表示ラベル
{ t:'se', id:'se_page' } // { t:'bgm', id:'bgm_storm', fade:500 }
{ t:'flag', id:'dedication_erasure' } // { t:'item', id:'first_edition' }
{ t:'param', key:'suspicion', delta:5 }
{ t:'log', key:'night_return', value:'before_23' }
{ t:'jump', scene:'chapter1' } // { t:'call', part:'rebuttal', args:{...} }
{ t:'chapterTitle', text:'第一章　一番の唄' } // { t:'end', endingId:'b1_true' }
```

`who` は `characters.js` のキー、地の文だけ `null`。`bg/cg/chara/se/bgm` のIDはmanifestに存在するIDを使います。`chara.pos` は `left|center|right`、`action` は `fadeIn|replace|fadeOut`。`voice` は将来用の任意項目です。

### 分岐

```js
{ t:'choice', prompt:'どうする？', options:[
  { label:'調べる', cond:{ flag:'dedication_erasure' }, effects:[{t:'param',key:'suspicion',delta:5}], goto:'study_done' },
  { label:'戻る', effects:[{t:'log',key:'study',value:'no'}], goto:'return_room' }
] }
{ t:'if', cond:{ and:[{flag:'dedication_erasure'},{param:'conscience',gte:2}] }, then:[{t:'say',who:'shiori',text:'……'}], else:[] }
```

`goto` は同一scene内の `{t:'label', id:'study_done'}` を指します。`label` は何も表示せず通過する専用ノードで、演出用の`stage`と兼用してはいけません。存在しないlabelへの`goto`は実行時にコンソールエラーとなり、静的検証でもエラーになります。effectsは `flag/item/param/log` ノードと同じ形で、順に適用されます。`if` の `then/else` は通常ノード配列です。

### 不変シナリオと実行スタック

シナリオ定義（各`scene.nodes`および分岐配列）は**実行時に決して変更しません**。`if` は条件に応じた配列を実行スタックへ積み、末尾で親フレームへ戻ります。セーブには`sceneId`と`executionStack`（各フレームの`path`と`index`）を保存します。したがって`if`の内部でセーブしても、ロード後に同じ分岐・同じ進行位置から再開できます。

`call`も同じ実行スタック上の現在ノードです。専用UIは完了後にeffectsを返し、そのノードを一つ進めるだけで親の分岐・sceneへ正しく復帰します。シナリオ配列の`splice`などによる展開は禁止です。

条件DSLは文字列式ではなく、次だけを再帰的に組み合わせます。

|形|意味|
|---|---|
|`{flag:'id'}` / `{item:'id'}`|所持判定|
|`{param:'trust',gte:30,lte:90}`|数値比較。`gte/lte/eq` を任意併用|
|`{countFlags:'past',gte:5}`|系統の所持数|
|`{log:{key:'x',equals:'y'}}`|証言ログ比較|
|`{and:[...]}` / `{or:[...]}` / `{not:...}`|論理結合|

未定義ID・未知の条件はfalseとして扱います。分岐用にJavaScript関数や文字列評価を混ぜないでください。

## フラグ・証拠・ログ

フラグ定義は `src/data/flags.js` に集中させます。

```js
{ id:'dedication_erasure', line:'past', name:'献辞の消し跡', desc:'説明', source:'第一章・書斎' }
```

`line` は `past`(🕯過去)、`plan`(📜計画)、`alive`(👁生存) のいずれかです。新規フラグは必ずここへ追記してからシナリオで参照します。`items.js` の証拠カードは `{id,name,desc}`。`log` はプレイヤーが口にした時刻・主張など、後の矛盾照合に使う値です。上書きされるため、発言履歴が必要ならキーを分けます。

## パラメータ

|キー|初期値・範囲|主要閾値・用途|
|---|---|---|
|`suspicion` 疑惑|10 / 0〜100|70以上で要注意、100で実行ルート失敗候補|
|`conviction` 悟郎の確信度|50 / 0〜100|30以下完封、70以上で要注意人物|
|`awareness` 察知|0 / 0〜100|50以上で五番の夜の標的化を開始|
|`conscience` 良心|0 / -10〜10|+3以上で告白・終幕台詞の柔らかい差分|
|`narrator` 語り手|0 / -10〜10|+側=栞、-側=探偵。コウナン代行ごとに-1|
|`agitation` 動揺|0 / 0〜100|60で宗玄の敬語が剥がれ、80で「お前」|
|`trust` コウナンの信頼度|0 / 0〜100|40で協力、70で防衛支援|
|`overknow` 知りすぎ|0 / 0〜10|2以上でコウナン個別マーク|

一回の通常変動は±1〜15、重大証拠は±20までを原則とします。上限下限はエンジンが丸めます。

## 特殊パートの呼び出し契約

`{t:'call',part,args}` は進行を止めて専用UIへ渡します。専用UIは終了時にeffects配列を返し、エンジンが同じ `applyEffect` で適用して次ノードへ進めます。α版では反論、共同推理、自由行動、手毬唄ボード、証言ログを実装済みです。

### 反論

```js
{ t:'call', part:'rebuttal', args:{ id:'day2_inquiry', nodes:[
 {id:'n1', claim:'毒は珈琲に混入された', responses:[
  {kind:'rebut', label:'反証', card:'menu_roster', result:{effects:[{t:'param',key:'conviction',delta:-15}], break:true}},
  {kind:'silence', label:'沈黙', result:{effects:[]}},
  {kind:'redirect', label:'転嫁', cond:{flag:'other_plan'}, target:'goko', result:{effects:[{t:'param',key:'conscience',delta:-1}]}}
 ]} ], initialConviction:50 } }
```

`kind` は `rebut|silence|redirect`。`card` はitemsまたはflagsのID、`cond` は共通条件、`result.effects` は共通effects。犯人しか知りえない反証には `{t:'param',key:'overknow',delta:1}` と疑惑増を結果へ明記します。反論試作のN1〜N3をこのまま転記できます。

### 共同推理

```js
{ t:'call', part:'jointReasoning', args:{ id:'wall_author', phases:[
 {id:'p1', title:'私は死んでいた', nodes:[{id:'n1', claim:'君たちは私の死体を見た', requirements:[['corpse_callus']], conanProxy:true, relicBonus:false, agitation:15}]}
 ], final:{id:'n10', requirements:[['acrostic']], conanProxy:false, relicBonus:true}, bravado:{triggerPhases:['p3','p4'], extraRequirement:1} } }
```

`requirements` は代替可能なカード組の配列（各内側配列は全枚数必須）。`conanProxy`、`relicBonus`、`agitation` で4フェイズ11ノード(N1〜N11)と最終局面を表現します。律の遺品での提示時は動揺を二倍にし、P3/P4を先に崩すと`bravado`により以後必要枚数を+1します。

### 自由行動

```js
{ t:'call', part:'freeAction', args:{ day:1, blocks:4, actions:[{id:'study',label:'書斎を調べる', reward:[{t:'flag',id:'dedication_erasure'}], risk:[{t:'param',key:'suspicion',delta:10}], encounter:'conan'}] } }
```

`blocks` 回だけ選択、各行動は報酬とリスクをeffectsで記述します。第一章の行動表（書斎、家政婦、共犯者A、犯行準備、観察、館探索）をこの形式に落とします。

### 手毬唄ボード

```js
{ t:'call', part:'temariBoard', args:{ verses:[{number:1, textId:'temariuta_1', slots:{dead:null, actor:null, meaning:null}}], cards:['onda','goko','poison'] } }
```

六番それぞれに`dead`（死者）、`actor`（実行者）、`meaning`（表・脚本・裏読み）カードを貼るUIです。正誤は`solutions`を追加して判定しても、物語上あえて未確定のままにしても構いません。

## アセット

`assets/manifest.json` の各行は `{id,kind,file,size,用途,生成方針}`。`kind` は `bg|chara|cg|ui`、背景・CGは1280x720、立ち絵は700x1200を基準にします。画像がない間はIDと用途入りCanvasプレースホルダが出ます。

探偵側の画像は既存キャラクターを描かず、役割ベースの完全オリジナル外見とします。特に赤い蝶ネクタイ、丸眼鏡など固有意匠は生成指示に入れません。表示名だけは `characters.js` の`detectiveNames`で一括差し替え可能です。
