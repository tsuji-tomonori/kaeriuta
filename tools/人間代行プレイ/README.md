# 人間代行プレイ

## 何を測る検査か

「矛盾文だけを手掛かりに、盤が実際に解けるか」を、人間の代わりに LLM エージェントで確かめます。

`tools/AIプレイ` の11ペルソナが定型の採点方針で遊ぶのに対し、こちらでは、その場で日本語を読んで推論する個体が遊びます。前者は設計の破綻検出、後者は難度の妥当性検証が目的です。

## 不正防止の設計

エージェントに渡す情報は、唄の本文、札の名前と注記と置ける欄、現在の盤、確定時に返る矛盾文だけです。

盤の判定値である「まことの盤の正確さ：N/6」は渡しません。実際のUIでは常時表示されるため、この検査は製品より厳しい条件で測っています。

`codex` は空の一時ディレクトリで `-s read-only` を指定して起動します。プロンプトにはリポジトリのパスも、作品名由来のファイル名も出しません。それでも読もうと思えば読めるため、stdout に正解表を読んだ形跡が出ていないか、毎回 `cheatSuspicion` として検査します。この検出器は、わざと正解表を読ませた対照実行で発火することを確認済みです。

## 使い方

```sh
node tools/人間代行プレイ/実行.mjs <model> <effort> [最大確定回数]
node tools/人間代行プレイ/集計.mjs
```

実行には `codex` CLI が必要です。課金を伴う外部呼び出しなので、CIでは回しません。生ログは `ログ/実行/` に生成され、Gitでは追跡しません。集計結果の `ログ/サマリ.json` は追跡します。生ログがなければ、集計は終了コード1で終わります。

## 実測結果

2026年7月31日、修正後のコードに対する結果です。

| モデル | effort | 解けた | 確定回数 | 正確さの推移 |
| --- | --- | --- | --- | --- |
| gpt-5.6-luna | low / medium / high / xhigh | ○ / ○ / ○ / ○ | 3 / 2 / 3 / 4 | 5→5→6 / 5→6 / 5→5→6 / 3→5→5→6 |
| gpt-5.6-terra | low / medium / high / xhigh | ○ / ○ / ○ / ○ | 3 / 2 / 2 / 2 | 4→5→6 / 5→6 / 5→6 / 5→6 |
| gpt-5.6-sol | low / medium / high / xhigh | ○ / ○ / ○ / ○ | 3 / 3 / 3 / 3 | 4→5→6 / 4→4→6 / 4→5→6 / 4→5→6 |

effort による差は出ていません。このパズルは推論の深さではなく、情報の有無で決まっています。

難所は2番の実行者欄（正解＝鬼灯宗玄）に集中しました。12本すべてが1回目で外し、誤配置は霧原栞13回、鬼灯剛蔵8回でした。「顔を失った被害者自身が実行者」という反転は、唄と札の注記だけからは引けていません。

落としたのは矛盾文でした。「読んだ者と書いた者を混ぜている」を読んで、宗玄へ到達しています。

意味の欄は初手からほぼ全員正解でした。難度が1欄に集中しているため、その欄の矛盾文の出来が、このパズル全体の成否を握っています。

## 限界

被験者はAIであって人間ではありません。日本語の読解ができることと、プレイヤーが画面のUIから同じ情報を読み取れることは別です。
